# local-review

Локальный просмотр git-диффа в браузере с комментариями к строкам и экспортом
в `.md` / буфер обмена для передачи AI-агенту.

Без сборки и без зависимостей: сервер на встроенных модулях Node, фронт — статика
(vanilla HTML/CSS/JS). Node.js 20+.

## Запуск

Из корня репозитория:

```bash
node review.js
```

(эквивалентно `node tools/local-review/review.js`; есть также `npm run review`)

Откроется браузер на `http://127.0.0.1:4321/`. Если порт занят — берётся следующий
свободный, фактический адрес печатается в консоль.

## Флаги

| Флаг | Значение |
| --- | --- |
| `--working` | рабочая копия vs `HEAD` — изменения staged + unstaged + untracked (по умолчанию) |
| `--staged` | индекс vs `HEAD` |
| `--base <rev>` | рабочая копия vs `merge-base(<rev>, HEAD)`; без значения по умолчанию `origin/main` |
| `--mode <m>` | то же самое явно: `working` \| `staged` \| `base` |
| `--port <n>` | стартовый порт (по умолчанию `4321`) |
| `--host <addr>` | адрес прослушивания (по умолчанию `127.0.0.1`) |
| `--cwd <dir>` | папка внутри репозитория (по умолчанию текущая) |
| `--no-open` | не открывать браузер |
| `-h`, `--help` | справка |

Примеры:

```bash
node review.js --staged
```

```bash
node review.js --base origin/develop --port 5000
```

Режим и базовую ревизию можно переключать прямо в шапке страницы, перезапуск не нужен.

## Работа в UI

- Клик по номеру строки (правая колонка — номера в файле **после** изменений) —
  комментарий к строке.
- Протяжка мышью по номерам строк (вниз или вверх, как в гитхабе) — комментарий
  к диапазону; выделение подсвечивается прямо во время протяжки, `Esc` отменяет.
- `Shift` + клик по другому номеру — расширить уже выбранное до диапазона.
- «+ комментарий к файлу» в шапке — комментарий без привязки к строке
  (бинарные и удалённые файлы).
- `Ctrl+Enter` — сохранить, `Esc` — отмена.
- `edit` / `delete` на карточке правят или удаляют только этот комментарий.
- «Очистить всё» — единственный способ снести все комментарии, и только после
  подтверждения в модалке. `Esc`, клик по фону, «Отмена» — ничего не удаляется.

## Формат экспорта

И `.md`-файл, и буфер обмена содержат одно и то же:

```
src/features/auth/model/store.ts:L42
Не мутируй входной dto, верни новый объект

src/shared/api/client.ts:L88-L96
Этот retry дублирует логику из interceptor, вынеси
```

- `path:L<n>` — одна строка, `path:L<start>-L<end>` — диапазон.
- Комментарий к файлу целиком экспортируется как просто `path` (без `:L`).
- Номера строк — реальные номера в файле после изменений, а не позиции внутри диффа.
- «Сгенерировать .md» кладёт в корень репозитория `review-<YYYY-MM-DD-HHmm>.md`
  и показывает путь. Экспорт (и в файл, и в буфер) **не** меняет комментарии.

## Хранилище

`.local-review/comments.json` в корне репозитория. Файл, не localStorage —
комментарии переживают перезагрузку страницы и перезапуск сервера.
При старте `.local-review/` добавляется в `.gitignore`, если его там нет.

Тула работает с git только на чтение (`git diff`, `git rev-parse`, `git ls-files`,
`git merge-base`) и никогда не пишет в исходники и не коммитит.

## Проверка

```bash
node tools/local-review/smoke.js
```

Скрипт создаёт временный git-репозиторий (коммиты, изменения, переименование,
удаление, untracked, бинарник, CRLF, кириллица с пробелами, файл на 3000 строк),
поднимает на нём настоящий сервер, дёргает все эндпоинты и проверяет инварианты:
экспорт не меняет комментарии; массовое удаление только с явным `confirm`;
комментарии переживают рестарт; номера строк в экспорте — реальные номера в файле.
Ненулевой код выхода при любом расхождении.

## API (если понадобится дёргать руками)

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/state?mode=&base=` | список изменённых файлов + счётчики комментариев |
| GET | `/api/diff?file=&mode=&base=` | дифф одного файла с реальными номерами строк |
| GET | `/api/comments` | все комментарии |
| POST | `/api/comments` | создать `{file, startLine, endLine, text}` |
| PUT | `/api/comments/<id>` | изменить текст |
| DELETE | `/api/comments/<id>` | удалить один |
| POST | `/api/comments/clear-all` | удалить все, только с `{"confirm": true}` |
| GET | `/api/export/text` | markdown-текст для буфера |
| POST | `/api/export/file` | записать `review-<...>.md` в корень репозитория |
