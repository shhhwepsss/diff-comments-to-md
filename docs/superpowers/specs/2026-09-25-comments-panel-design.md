# local-review: панель всех комментариев и старые комментарии

Дата: 2026-09-25
Статус: согласовано в чате, к реализации
Макет: https://claude.ai/artifact/KyCTZWCfozEeCTn9WKFWZ6 (вариант C)

## Задача

Сейчас увидеть все комментарии ревью можно только пройдя по файлам: счётчик
«Комментарии N» в шапке — это `span`, на него нельзя нажать
(`web/src/components/AppHeader.tsx:92`). Нужна панель со списком всех
комментариев, по которой можно пройти подряд, не теряя дифф.

Из трёх вариантов макета выбран **C — закреплённая панель**: не модальная,
встаёт справа от диффа и сужает его, дифф остаётся рабочим.

Вторая часть задачи (решено делать вместе): комментарии, написанные к другому
состоянию кода, не прятать, а показывать **серыми** с пометкой коммита — и в
панели, и в редакторе.

## Зафиксированные решения

| Тема | Решение |
|---|---|
| Вид | вариант C, панель справа от `<main>` в `.rv-diff-layout` |
| Открыть/закрыть | кнопка-счётчик «Комментарии N» в шапке + настраиваемая клавиша |
| Клавиша по умолчанию | **не задана** (как у Zen) |
| Состояние открыта/закрыта | один флаг в `localStorage`, общий для Zen и обычного вида |
| Панель в Zen | видна, если открыта |
| Ширина | тянется ручкой, хранится в `localStorage`, clamp как у сайдбара |
| Порядок | как в экспорте: общие → файлы в порядке диффа по строкам → «нет в диффе»; старые — отдельной серой группой внизу |
| Старый комментарий | «свой коммит» комментария не входит в то, что показано сейчас (см. ниже) |
| Старые в редакторе | показываются серыми с чипом коммита (сейчас скрыты) |
| Клик по старому | переход к строке в **текущем** диффе + отдельная кнопка «Открыть в `<sha>`» |
| `Esc` | панель не закрывает (он выходит из Zen, `App.tsx:83-85`) |
| Экспорт .md | не меняется |

## За рамками

- Варианты A (drawer) и B (модалка) из макета.
- Пересчёт привязки старого комментария к строке, если код сдвинулся.
- Хранение HEAD/режима в самом комментарии: «свой коммит» вычисляется по времени.
- Пометка старых комментариев в экспорте.

## 1. Панель

Новый компонент `web/src/comments/CommentsPanel.tsx` (+ `comments-panel.css`).
Рендерится в `DiffScreen` внутри `.rv-diff-layout` после `<main className="rv-content">`.

- **Состояние.** `local-review:comments-panel` (`'1'`/`'0'`) — модуль
  `web/src/lib/commentsPanel.ts` по образцу `lib/zen.ts` (parse/read/write,
  try/catch вокруг storage). Ширина — `local-review:comments-panel-width`,
  clamp и parse — через общие функции из `diff/sidebarWidth.ts`
  (обобщить их параметрами min/default, не копировать).
- **Кнопка в шапке.** `rv-header__count` становится `Button` с
  `aria-pressed={open}` и тем же `CounterLabel`. Кнопка «N вне выбора»
  остаётся как есть.
- **Клавиша.** В `KEYBINDING_ACTIONS` (`lib/keybindings.ts:34`) добавить
  `{ id: 'commentsPanel', label: 'Панель всех комментариев' }`, дефолт `''`.
  Обработчик — рядом с Zen в `App.tsx:80-94`, только на экране диффа.
- **Шапка панели:** заголовок, позиция «3 / 10», ↑ / ↓, «Закрыть».
- **Фильтр:** Все / В файлах / Общие / Нет в диффе / Старые.
- **Строка списка:** имя файла + `L12`/`L12–L18` (или «Общий комментарий»),
  дата, текст в 2 строки. Текущая строка раскрыта целиком и показывает
  действия: «К строке», «Открыть в `<sha>`» (только у старых), «Изменить»,
  «Удалить». Правка — существующий `CommentForm` и `review.drafts`
  (`editDraftKey`), удаление — `review.deleteComment`.
- **Навигация:** `j`/`k` и ↑/↓ — следующий/предыдущий, пока панель открыта и
  фокус не в поле ввода. Переход на комментарий с файлом делает «К строке».
- **Обратная синхронизация:** клик по карточке комментария в диффе делает его
  текущим в панели и прокручивает список к нему.
- **Порядок и фильтры** — чистый модуль `web/src/comments/panelList.ts`
  (сортировка, группы, фильтр, следующий/предыдущий).

## 2. Переход к строке

- `ReviewContext` получает `revealComment(id)`: открывает файл комментария
  (`selectFile`, если файл другой) и ставит `reveal = { commentId, nonce }`.
- `DiffPane` по `reveal`:
  - файл в режиме «Просмотр» (markdown) переключает на «Код»;
  - если комментарии файла скрыты кнопкой в заголовке, показывает их
    (`setFileHidden(..., false)`);
  - если строка комментария есть в документе — передаёт в `DiffEditor` строку
    для прокрутки; иначе прокручивает к блоку `.rv-file-comments`.
- `DiffEditor` получает проп `reveal: { line, nonce } | null` и делает
  `EditorView.scrollIntoView(pos, { y: 'center' })` + короткую подсветку строк
  комментария. Строки с комментариями никогда не сворачиваются
  (`diff/cm/collapse.ts:9-11`), поэтому цель всегда видна.
- Комментарий без файла (общий) и файл «нет в диффе»: «К строке» нет; для
  «нет в диффе» — открыть файл (`selectFile`), как в сайдбаре.

## 3. Старые комментарии

### Данные

- Сервер: в `Commit` добавить `committedAt` (ISO).
  - Локально: `%cI` в формате `git log` (`lib/commits.js:87`).
  - PR: `entry.commit.committer.date` в `mapGhCommit` (`lib/routes/commits.js:31`).
  - Тип `Commit` в `web/src/api/types.ts`.
- Committer date, а не author date: rebase/amend создают новый коммит, и
  комментарий, написанный до него, должен стать старым.
- История коммитов грузится **во всех режимах** (сейчас — только в «Коммиты»).
  Тот же endpoint; для PR ответ кешируется на 120 с (`lib/routes/commits.js:13`).
  В режимах кроме «Коммиты» рельс не рисуется — нужны только данные.

### «Свой коммит» комментария

Чистый модуль `web/src/review/commentAge.ts`.

1. Есть `comment.commit` → свой коммит = `comment.commit.to`.
2. Нет → первый коммит истории, у которого `Date.parse(committedAt) > Date.parse(createdAt)`.
3. Такого нет → комментарий к незакоммиченным изменениям (`null`).

Даты сравниваются через `Date.parse`, не строками (у `%cI` локальный сдвиг
часового пояса, у `createdAt` — `Z`).

Сценарий, который обязан работать: в Staged написан комментарий → `git commit`
→ свой коммит комментария = этот новый коммит (HEAD). В режиме «Коммиты» с
выбранным HEAD он **не серый**; в Staged и «Рабочей копии» — серый, потому что
этот код уже не в показанном диффе.

### Когда комментарий серый

| Вид | Серый, если |
|---|---|
| Рабочая копия, Staged | свой коммит не `null` (после комментария был коммит) |
| Base | свой коммит не `null` и не входит в коммиты ветки от точки ветвления |
| Коммиты (локально), PR-коммиты | свой коммит вне выбранного диапазона (`null` — тоже вне) |
| PR «Все изменения» | свой коммит не входит в коммиты PR |

Комментарий, чей свой коммит не найден в загруженной истории (история обрезана
или переписана), — серый.

### Показ

- **Редактор.** Фильтр «вне выбора» в `DiffPane.tsx:148-156` убрать: старые
  комментарии рисуются на своей строке, как обычные, но с классом
  `rv-comment--stale` (приглушённый цвет) и чипом
  «к `<sha>` · строка могла сместиться».
- **Панель.** Группа «Старые» внизу списка, серым, с тем же чипом.
- **«Открыть в `<sha>`».** Локально: режим «Коммиты» + выбор этого коммита
  (`setMode('commits')`, `setCommitSelection`); PR: `setPrCommitsView(true)` +
  выбор. Затем файл и строка (`revealComment`). Над диффом плашка
  «Вы смотрите старый коммит `<sha>` · Вернуться»; «Вернуться» восстанавливает
  прежний дескриптор (режим, base, диапазон).
- Для комментария без записанного коммита «Открыть в» ведёт в первый коммит
  после комментария (п. 2 выше).

## Ограничения (приняты в чате 2026-09-25)

1. Старый комментарий рисуется на строке с тем же номером; если код сдвинулся,
   он окажется не там. Только пометка «строка могла сместиться».
2. «Свой коммит» по времени — эвристика: при коммите изменений по частям
   покажет не тот коммит; для PR время коммитов — GitHub, время комментариев —
   локальные часы.
3. После rebase/amend все комментарии, написанные до него, становятся серыми,
   даже если код не менялся.
4. История обрезана (PR — 250 коммитов, `lib/routes/commits.js:19`; локально —
   лимит `listCommits`). Комментарий, чей коммит за пределами — серый.
5. Сравнивается `createdAt`: правка текста не делает комментарий актуальным.
6. Экспорт в .md не меняется.
