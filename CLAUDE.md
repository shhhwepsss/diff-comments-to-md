# CLAUDE.md

Инструкции для Claude Code в этом репозитории. Устройство приложения —
в `tools/local-review/README.md`, дизайн-документы — в `docs/superpowers/`.

## Каждая фича начинается с прототипа

Прежде чем писать код фичи (в том числе UI-изменения в существующих экранах),
сделай прототип и согласуй его с пользователем.

1. **Спроси пользователя, в каком виде делать прототип** (через
   `AskUserQuestion`, не выбирай сам):
   - **HTML-файл в репозитории** — `docs/prototypes/<ГГГГ-ММ-ДД>-<фича>.html`,
     один самодостаточный файл, коммитится вместе с фичей;
   - **Артефакт claude.ai** — публикуется инструментом `Artifact`, ссылка
     отдаётся пользователю.
2. **Прототип выглядит как приложение сейчас.** Перед вёрсткой прочитай
   текущие компоненты и стили (`tools/local-review/web/src/`, Primer,
   `styles/dark-slate.css`, `styles/global.css`) и повтори их: шапку, дерево
   файлов, панель диффа, цвета, отступы, шрифты, иконки (Octicons), светлую и
   тёмную тему. Новое показывай в контексте настоящего экрана, а не на пустой
   странице.
3. **Прототип функциональный.** Кнопки, фильтры, переключатели, клавиши и
   состояния (пусто, загрузка, ошибка, много данных) работают на правдоподобных
   моковых данных — пользователь должен потрогать фичу, а не только посмотреть.
4. **Код фичи — только после одобрения прототипа.** Правки пользователя вноси
   в прототип (тот же файл / тот же артефакт), пока он не скажет «делаем».
   Готовая фича должна совпадать с одобренным прототипом.
