# local-review

Просмотр диффа в браузере с комментариями к строкам и экспортом в `.md` / буфер
обмена для передачи AI-агенту.

Сервер — на встроенных модулях Node, без runtime-зависимостей. Фронт — React +
[Primer](https://primer.style) (дизайн-система GitHub) + CodeMirror 6 для диффа,
собирается Vite в `tools/local-review/dist/`. Все npm-пакеты — `devDependencies`:
они вшиваются в бандл, серверу не нужны.

## Два режима

Один сервер, одна вёрстка, две страницы. Комментирование, редактирование,
удаление и экспорт на обеих страницах работают одним и тем же кодом.

| | Локальная папка | GitHub PR |
| --- | --- | --- |
| Откуда дифф | `git diff` в выбранном репозитории | `gh pr diff`, локальный клон не нужен |
| Выбор объекта | папка выбирается прямо в UI | поиск PR-ов по репозиторию и запросу |
| Комментарии | `<репозиторий>/.local-review/comments.json` | `~/.local-review/pr/<host>__<owner>__<repo>__<number>.json` |
| Экспорт `.md` | в корень репозитория | в `~/.local-review/exports/` |
| Навигация по коду | LSP по репозиторию | по тексту файлов диффа; с клоном (`gh repo clone` или свой, привязка в `~/.local-review/pr-clones.json`) — LSP по клону |

PR больше 300 файлов (или 20000 строк) GitHub одним диффом не отдаёт (`HTTP 406`);
тогда список файлов берётся постранично из `gh api .../pulls/<n>/files`. Пределы
самого GitHub — 3000 файлов на PR и 300 на диапазон коммитов: если предел
достигнут, над диффом появляется плашка «Список файлов неполный» с числом
показанных файлов.

Адреса экранов: `#/local` — выбор папки, `#/local/<путь>` — дифф репозитория,
`#/pr` — поиск PR-ов, `#/pr/<host>/<owner>/<repo>/<number>` — дифф PR-а,
`#/settings` — настройки (`#/settings/<куда вернуться>`, если открыты
шестерёнкой из шапки).
К адресу диффа добавляется открытый вид:
`…?mode=<working|staged|base|commits>&base=<ref>&from=<sha>&to=<sha>&file=<путь>`.
Такую ссылку можно открыть в новой вкладке (средняя кнопка или Ctrl+клик по
файлу в дереве) — откроется тот же дифф на том же файле; она же уезжает в
`#/settings/<куда вернуться>`, так что «Назад» из настроек возвращает к тому же
виду. Выбор файла — шаг истории браузера: «Назад» возвращает к предыдущему
файлу; смена режима, base или диапазона переписывает текущую запись истории.
Строка PR-а в результатах поиска и её кнопка «Открыть» — тоже ссылки: обычный
клик открывает PR в этой же вкладке, средняя кнопка, Ctrl+клик или «Открыть в
новой вкладке» из контекстного меню — в новой, а список остаётся на месте.
Неизвестные параметры игнорируются: адрес сводится к значениям по умолчанию.
Последний открытый экран запоминается в `~/.local-review/state.json` и
восстанавливается при следующем запуске.

`~/.local-review/` **не чистится автоматически**. Его путь и число хранимых PR-ов
показаны на экране поиска PR-ов, чтобы каталог не рос незаметно.

## Требования

- Node.js 20.19+ (или 22.12+) — этого требует Vite для сборки фронта.
- Для режима GitHub PR — установленный [GitHub CLI](https://cli.github.com) и
  выполненный `gh auth login`. Проверить: `gh auth status`.

Без `gh` локальный режим работает полностью, а страница PR показывает, что
именно нужно сделать, — не пустой экран и не stack trace.

## Запуск

Один раз после клонирования и после каждого `git pull`:

```bash
npm install   # ставит devDependencies и собирает UI (скрипт prepare → npm run build)
```

Потом:

```bash
node review.js
```

Если UI не собран, `review` сразу пишет «UI не собран: выполни `npm run build`» и
выходит — пересобрать можно и отдельно: `npm run build`.

(эквивалентно `node tools/local-review/review.js`; есть также `npm run review`)

Откроется браузер на `http://127.0.0.1:4321/`. Если порт занят — берётся следующий
свободный, фактический адрес печатается в консоль.

### Из любого проекта: команда `review`

В `package.json` объявлен `bin` `review`. Один раз в корне этого репозитория:

```powershell
npm link
```

После этого в любом проекте:

```powershell
cd C:\path\to\other-project
review                 # или: review --staged / review --base origin/main
```

`npm link` ставит symlink, поэтому правки сервера подхватываются без
переустановки. Правки фронта — после `npm run build`.
Удалить команду: `npm unlink -g diff-comments-to-md`.

Запускать из корня репозитория **не обязательно**: если текущая папка не
репозиторий, откроется экран выбора папки. Если она подкаталог репозитория,
тула спросит, читать ли дифф из корня, и без подтверждения ничего не откроет.

## Флаги

| Флаг | Значение |
| --- | --- |
| `--working` | рабочая копия vs `HEAD` — изменения staged + unstaged + untracked (по умолчанию) |
| `--staged` | индекс vs `HEAD` |
| `--base <rev>` | рабочая копия vs `merge-base(<rev>, HEAD)`; без значения по умолчанию `origin/main` |
| `--mode <m>` | то же самое явно: `working` \| `staged` \| `base` |
| `--port <n>` | стартовый порт (по умолчанию `4321`) |
| `--host <addr>` | адрес прослушивания (по умолчанию `127.0.0.1`); он же разрешается в заголовке `Host` (см. «Что тула не делает») |
| `--cwd <dir>` | папка внутри репозитория (по умолчанию текущая) |
| `--no-open` | не открывать браузер |
| `-h`, `--help` | справка |

Флаги задают только стартовое состояние: и режим, и базовую ревизию, и сам
репозиторий можно менять прямо в UI, перезапуск не нужен.

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `LOCAL_REVIEW_HOME` | каталог конфига вместо `~/.local-review` |
| `LOCAL_REVIEW_GH_BIN` | путь к `gh`; нужен только smoke-тесту для подстановки фикстур |
| `LOCAL_REVIEW_GH_DEBUG` | `1` — печатать в stderr строку на каждый запуск `gh`: длительность, номер попытки, исход. Так видно, где ждём GitHub |
| `LOCAL_REVIEW_STATIC_DIR` | каталог собранного UI вместо `tools/local-review/dist`; нужен smoke-тесту |

## Работа в UI

- Слева — дерево изменённых файлов со статусом и счётчиком комментариев, сверху
  «Найти файл» — поиск по части пути без учёта регистра. Файлы, у которых есть
  комментарии, но которых нет в текущем диффе, — в секции «Вне диффа».
- Кнопка `…` рядом с поиском раскрывает правила «Показывать файлы» и «Скрывать
  файлы» — regexp по полному пути, с учётом регистра, как files to include /
  exclude в VS Code. Файлы, не прошедшие правила, не пропадают, а уходят в
  серую секцию «Скрыто правилами» в конце дерева; поиск находит и их. Неверный
  regexp подсвечивается и не применяется. Правила живут до перезагрузки
  страницы; пока они действуют при свёрнутых полях, на кнопке горит точка.
- Дифф — unified, как на GitHub: две колонки номеров (до и после), подсветка
  синтаксиса, подсветка изменённых слов. Неизменённые участки свёрнуты, клик по
  «Показать N строк» разворачивает. Строки с комментариями не сворачиваются никогда.
- Клик по номеру строки — комментарий к строке. Комментарии привязаны к номерам
  в файле **после** изменений; к удалённым строкам комментарий не ставится.
- Протяжка мышью по номерам строк (вниз или вверх, как в гитхабе) — комментарий
  к диапазону; выделение подсвечивается прямо во время протяжки, `Esc` отменяет.
- `Shift` + клик по другому номеру — расширить уже выбранное до диапазона.
- **Подсветка вхождений.** Клик по слову в коде (или выделение ровно одного
  слова, например двойным кликом) подсвечивает все вхождения этого слова
  целиком во всём файле — по тексту, без разбора языка: в добавленных,
  контекстных и удалённых строках, в комментариях и строковых литералах тоже
  (`_` и `$` — часть слова: `path` не найдётся внутри `_path` или `pathname`).
  Текущее вхождение ярче. В шапке файла — «слово N из M» и стрелки ↑/↓:
  переход к предыдущему / следующему по кругу, с прокруткой (свёрнутый участок
  при этом разворачивается). Справа у кода — полоса с метками всех вхождений
  на высоту видимой части файла; клик по метке — переход к нему. Подсветка
  одна на экран: клик в другом файле ленты переносит её туда. Сбрасывают её
  `Esc` (в Zen первый `Esc` снимает подсветку, второй — выходит из Zen), клик
  мимо слова или выделение больше одного слова. Удалённые строки
  подсвечиваются через CSS Custom Highlight API (Chrome 105+, Safari 17.2+,
  Firefox 140+); в браузере без него они считаются в «N из M», но не
  закрашиваются.
- «Комментарий к файлу» в меню «⋯» шапки файла — комментарий без привязки к строке
  (бинарные и удалённые файлы).
- «Общий комментарий…» в меню «Ревью» шапки (со своим счётчиком) — замечания ко всему ревью, а не
  к строке, как summary ревью на GitHub. Открывает боковую панель: список общих
  комментариев (правка / удаление) и форма для нового. Их может быть несколько.
  Несохранённый текст (новый комментарий и начатая правка) переживает закрытие
  панели и хранится в памяти до сохранения; перезагрузка страницы его сбрасывает.
- `Ctrl+Enter` — сохранить, `Esc` — отмена.
- **Zen** (меню «Вид» в шапке или «⋯» в шапке файла) — дифф и дерево файлов, больше
  ничего: шапка приложения, лента коммитов, плашка про незакоммиченное и
  заголовок PR не рисуются, отступы и рамки вокруг диффа убраны. При окне
  высотой 860 px это 827 px под дифф — 41 строка кода вместо 33 в обычном виде
  и вместо 21 в режиме «Коммиты».
  Выход — `Esc` или кнопка «Выйти из Zen» в шапке файла; шапка липкая, так что
  кнопка видна всё время, пока листаешь файл. Когда шапки файла нет (файл не
  выбран, пустая история, дифф не загрузился) та же кнопка появляется в правом
  нижнем углу. Режим запоминается в `localStorage` и переживает
  перезагрузку, но не уезжает по ссылке: в адресе его нет.
  В Zen не видно, какой диапазон коммитов выбран, и стрелки `←`/`→` его не
  двигают — диапазон выбирают до входа в режим. На страницах выбора папки, поиска
  PR и настроек Zen не действует: шапка там нужна для навигации.
- **Репозиторий на экране поиска PR-ов** выбирается из списка: клик по полю
  открывает репозитории, куда есть доступ (свои, чужие как коллаборатор и
  доступные через организацию), свежий пуш первым и с датой пуша в строке.
  Набранный текст фильтрует список по любой его части, так что имя репозитория
  ищется без владельца. Выбор строки сразу запускает поиск.
  Репозитория нет в списке — впиши `owner/repo` руками, как раньше; пустое
  поле по-прежнему значит «все мои PR-ы». `Esc` очищает поле.
  Список берётся у `gh` при каждом заходе на экран (около полутора секунд) и не
  кешируется; поиск PR-ов его не ждёт. Не загрузился — под полем написано,
  почему, а поле остаётся обычным вводом.
- **Папку можно отметить просмотренной**: наведи на неё в дереве файлов — справа
  появится ✓; клик отмечает все файлы папки, которые сейчас видны в дереве
  (поиск и правила показа учитываются), повторный клик снимает отметки. С
  клавиатуры — `Ctrl+Shift+U` на папке. Просмотренная целиком папка остаётся с
  зелёной ✓, частично — показывает «2/5».
- **`Alt+V` — «просмотрено» для открытого файла.** Снимает отметку, если она
  есть; иначе отмечает файл и открывает следующий непросмотренный в порядке
  дерева (по кругу). Порядок берётся по всем файлам диффа, без учёта поиска и
  правил показа. Сочетание меняется или снимается в настройках.
- **Устаревшие отметки «просмотрено» удаляются сами.** Отметка действует, пока
  дифф файла тот же, что в момент отметки; когда он меняется, запись в файле
  ревью остаётся, но уже не действует. При старте сервер один раз, в фоне,
  проходит по отметкам репозитория, в котором запущен, и удаляет те, чей дифф
  изменился, чей файл ушёл из диффа или чей вид больше нельзя построить
  (диапазон с исчезнувшими коммитами, удалённая ветка-база). Работает только
  git, в сеть сервер при старте не ходит: отметки PR-а чистятся, когда этот PR
  открывают в первый раз за запуск, и только в открытом виде («все изменения»
  или выбранный диапазон коммитов).
  Размен: раньше, если вернуть файл ровно в прежнее состояние, отметка снова
  начинала действовать; после чистки записи уже нет, и файл придётся отметить
  заново. Не чистятся отметки из старого формата файла (без деления на режимы)
  и отметки репозиториев, открытых через «Папку», а не тем, где запущен сервер.
- **Горячие клавиши** назначаются на странице настроек (`#/settings` →
  «Горячие клавиши»). По умолчанию заданы `Alt+V`, `Alt+A` (переключить режим:
  один файл / все файлы), `F12` (к определению), `Shift+F12` (ссылки),
  `Ctrl+F12` (реализации), `Alt+Shift+H` (иерархия вызовов) и `Alt+←` /
  `Alt+→` (назад и вперёд по переходам, см. «IDE-режим»). Клавиша — буква, цифра, `F1`–`F12`
  или стрелка `←` / `→` (стрелка — только с `Ctrl`, `Alt` или `Meta`), с
  модификаторами или без; сочетание не срабатывает, пока курсор в
  поле ввода. `Esc` закрывает панель ссылок, затем выходит из Zen; назначить
  его нельзя.
  Привязка запоминает физическую клавишу, а не символ, — сочетание, заданное на
  латинской раскладке, работает и на кириллической. Хранится в
  `~/.local-review/settings.json` (`keybindings`).
- Карандаш / корзина на карточке правят или удаляют только этот комментарий.
- У markdown-файлов (`.md`, `.markdown`, `.mdx`, …) в шапке файла переключатель
  «Код» / «Просмотр» (две иконки): просмотр рендерит новую версию файла (у удалённого —
  прежнюю) как GitHub, только для чтения. HTML санитизируется; относительные
  ссылки и картинки не открываются. Внешние картинки не грузятся, пока не нажать
  «Показать внешние картинки» (для этого файла, до перезагрузки). Комментарии к
  строкам — в режиме «Код»; недописанный комментарий переживает переключение.
  Переключатель общий для всех таких файлов; сделать его отдельным для каждого
  файла можно в настройках («Вид файла»).
- У HTML-файлов (`.html`, `.htm`, `.xhtml`) тот же переключатель: «Просмотр»
  показывает страницу как в браузере — в изолированном iframe, на белом фоне,
  высотой по содержимому. По умолчанию скрипты страницы не выполняются, а из
  сети не грузится ничего (CSP). «Запустить скрипты» включает её инлайн-скрипты
  — без доступа к приложению и его API и без сетевых запросов; «Загрузить
  внешние ресурсы» разрешает внешние картинки, стили, шрифты (и скрипты с
  запросами, если скрипты включены). Оба выбора — для этого файла, до
  перезагрузки. Ссылки `https://…` открываются в новой вкладке, якоря `#…`
  прокручивают, относительные ссылки не открываются.
- Блок ```` ```mermaid ```` в просмотре рисуется диаграммой (`erDiagram`,
  `flowchart`, `sequenceDiagram`, …) в цветах текущей темы. Библиотека лежит в
  сборке и подгружается только для документа с таким блоком. Блок, который
  mermaid не разобрал, остаётся кодом со строкой об ошибке. Блок с внешним
  адресом (`https://…`, `//host/…`) не рисуется вовсе: иначе картинка из него
  загрузилась бы с чужого сервера.
- Клик по диаграмме (или кнопка «Развернуть» на ней) открывает её на всё окно.
  Колесо — масштаб к курсору (щипок на тачпаде тоже), перетаскивание — сдвиг,
  двойной клик — 1:1 или вписать. Клавиши: `+` / `-` — масштаб, `0` — вписать,
  `1` — 1:1, стрелки — сдвиг, `Esc` — закрыть. Масштаб — от 10% до 800%;
  открывается диаграмма вписанной в окно, маленькая при этом увеличивается.
- «Очистить всё…» (последний пункт меню «Ревью») — единственный способ снести все комментарии, и только после
  подтверждения в диалоге. `Esc`, крестик, «Отмена» — ничего не удаляется.
- Тема — светлая / тёмная / как в системе, перенос длинных строк, «Один файл» /
  «Все файлы» и Zen — в меню «Вид» (иконка с ползунками справа в шапке); перенос
  строк есть ещё в «⋯» шапки файла, чтобы переключать его и в Zen. Выборы
  запоминаются в браузере. На экранах выбора папки, поиска PR и настроек тема —
  отдельной кнопкой справа.
- **Шапка диффа** — одна строка: слева имя репозитория (или `owner/repo #N`),
  режим диффа и «перечитать»; справа «Комментарии», меню «Ревью» (общий
  комментарий, «Скопировать всё», «Сгенерировать .md», «Очистить всё…»), меню
  «Вид» и шестерёнка настроек. Клик по имени репозитория показывает полный путь
  и ведёт к выбору другой папки или PR-а; полный путь — и в подсказке при
  наведении. В шапке файла — путь (папка приглушена), `+/−`, счётчик
  комментариев, «Код» / «Просмотр» (где есть), «Просмотрено» и «⋯»: комментарий
  к файлу, скрыть / показать комментарии, перенос строк, Zen.

## IDE-режим: навигация по коду

Для локальной папки (и для GitHub PR с локальным клоном, см. ниже) дифф умеет
то, что ждёшь от IDE, — с помощью language server (LSP), который уже установлен
у вас. Сам инструмент ничего не ставит.

- **Перейти к определению**: `Ctrl`+клик по символу (на macOS — `⌘`+клик; с
  зажатым модификатором символ под мышью подчёркивается как ссылка), пункт
  «Перейти к определению» в меню по правой кнопке на символе или `F12` на
  слове под курсором (сначала кликните по слову). `Shift`+правая кнопка —
  обычное меню браузера.
- **Подсказка при наведении**: сигнатура и документация символа
  (`textDocument/hover`), с задержкой ~350 мс; в ней же кнопки «Определение»,
  «Ссылки», «Реализации» и «Кто вызывает» (последние две — когда по сигнатуре
  видно, что они имеют смысл: у интерфейса нет вызовов, у функции —
  реализаций).
- **Ссылки, реализации, иерархия вызовов** — в боковой панели справа: пункты
  «Найти ссылки» (`Shift+F12`), «Реализации» (`Ctrl+F12`) и «Иерархия
  вызовов» (`Alt+Shift+H`) в меню по правой кнопке, кнопки подсказки или
  сочетание на слове под курсором. В шапке панели — имя символа и его вид
  (функция, метод, класс…), вкладки:
  - «Ссылки» (`textDocument/references`, вместе с объявлением) и «Реализации»
    (`textDocument/implementation`) — места, сгруппированные по файлам (файл,
    откуда спросили, первым; файлы вне репозитория — последними, серым и без
    перехода), у файла — счётчик, у места — номер строки и сама строка с
    подсвеченным символом. Строки сервер берёт из открытого документа (в
    Staged / Коммитах — показанной версии) или с диска; файлы вне репозитория
    не читаются.
  - «Вызовы» с переключателем «Кто вызывает / Что вызывает»
    (`prepareCallHierarchy`, затем `incomingCalls` / `outgoingCalls`). Дерево
    раскрывается лениво — каждый уровень отдельным запросом по клику на
    треугольник; функция, уже встреченная выше по ветке, помечается
    «рекурсия» и не раскрывается. Клик по вызывающему ведёт к месту вызова,
    по вызываемому — к его объявлению. Клавиатура: `↑` `↓`, `→` раскрыть /
    войти, `←` свернуть / к родителю, `Home` / `End`, `Enter` — перейти.

  Клик по месту — обычный переход (шаг истории «Назад/Вперёд», строка
  мигает). Панель занимает место панели комментариев (ширина и перетаскивание
  у них общие): открытая панель комментариев на это время прячется и
  возвращается, когда панель ссылок закрыта (`×` или `Esc`); кнопка
  «Комментарии» сразу отдаёт место комментариям. Две панели рядом оставили бы
  диффу узкую полосу. В Zen панель работает так же; первый `Esc` закрывает
  её (если подсвечены вхождения — сначала снимает подсветку), следующий
  выходит из Zen. Если сервер не умеет метод (нет `referencesProvider`,
  `implementationProvider` или `callHierarchyProvider` в его capabilities),
  вкладка так и говорит: «tsgo не поддерживает …».
- **Куда ведёт переход.** Цель в файле диффа — открывается этот файл и
  прокручивается к строке (строка мигает, символ подсвечивается как при
  подсветке вхождений). Цель вне диффа — файл открывается целиком (плашка «вне
  диффа») и попадает в секцию дерева «Открыто через навигацию» (× убирает его
  оттуда). Цель вне репозитория (библиотека, JDK) — сообщение, куда указал
  сервер; место внутри `.git/` в списках панели показывается серым с пометкой
  «служебный .git» и не открывается.
- **Комментарии в файлах вне диффа.** В файле, открытом переходом, номера
  строк кликабельны так же, как в диффе: клик — комментарий к строке,
  протяжка или `Shift`+клик — к диапазону, «⋯ → Комментарий к файлу» — ко
  всему файлу; правка и удаление — как везде. Это обычные комментарии
  (`file`, `startLine`, `endLine` — номера строк файла на диске): они видны в
  панели комментариев (группа «Вне диффа»), попадают в экспорт `.md` и в
  буфер, а после перезагрузки файл лежит в секции дерева «Вне диффа» и
  по-прежнему открывается целиком с комментариями на своих строках (если файла
  на диске уже нет — только список комментариев). Для PR это работает, когда у
  него есть клон.
- **Назад / Вперёд**: кнопки ← → в шапке файла, `Alt+←` / `Alt+→`, а также
  кнопки браузера и мыши — это одна история: каждый переход — шаг истории
  браузера, адрес несёт `file=` и `line=`, и «Назад» возвращает к строке, с
  которой ушли. Если позади в ревью ничего нет, `Alt+←` остаётся браузеру.
- Навигация работает в добавленных и неизменённых строках (сторона «после»).
  У удалённых строк файла на диске нет — там только подсветка вхождений.
- В режимах **Staged** и **Коммиты** серверу отправляется показанный текст
  файла (виртуальный документ через `didOpen`/`didChange`), поэтому позиции
  совпадают с экраном; остальной проект сервер видит в состоянии рабочей
  копии. Файлы, открытые с диска, перечитываются, если изменились.
- **Индикатор в шапке файла**: «LSP · tsserver» (серая точка — найден, ещё не
  запущен; зелёная — работает), «индексация…» / «запуск…», «LSP · ошибка» (в
  подсказке — хвост stderr сервера), «LSP не найден» — в подсказке, что
  установить. Для файлов, у языка которых сервера нет вовсе, индикатора нет.
- **Настройки → «Навигация по коду (LSP)»**: какие серверы найдены (и где),
  что запущено. **Настройки → «Горячие клавиши»**: «Перейти к определению»
  (`F12`), «Найти ссылки» (`Shift+F12`), «Реализации» (`Ctrl+F12`),
  «Иерархия вызовов» (`Alt+Shift+H`), «Назад» (`Alt+←`), «Вперёд» (`Alt+→`)
  переназначаются, как остальные.

### GitHub PR: локальный клон

У PR-а файлов на диске нет, поэтому над его диффом плашка **«Нет локального
клона — навигация по тексту…»** с кнопками **«Клонировать…»** и **«Указать свой
клон»**.

- **Без клона** навигация идёт по тексту файлов диффа (их новых версий):
  `Ctrl`+клик / `F12` ищет строки, объявляющие слово (`function`, `class`,
  `interface`, `type`, `enum`, `const` / `let` / `var`, методы; для Python
  `def` / `class`, для Go `func` / `type`, для Java / Kotlin / Rust / Ruby /
  PHP / C — свои простые шаблоны). Одно найденное объявление открывается
  сразу, несколько — списком во вкладке «Объявления» панели (с пометкой, что
  поиск по тексту не знает, какое из них нужное); клик по самому объявлению
  ищет его вхождения. `Shift+F12` — все вхождения слова целиком по файлам
  диффа, включая комментарии и строки. Подсказка при наведении, «Реализации» и
  «Иерархия вызовов» выключены (в меню — с пояснением «нужен локальный клон»),
  индикатор в шапке файла — «По тексту».
- **«Клонировать…»** — диалог с папкой (по умолчанию `~/projects/<repo>`; её
  не должно быть, или она пустая) и командами, которые выполнит сервер:
  `gh repo clone <owner>/<repo> <папка>`, затем `gh pr checkout <номер> --repo
  <owner>/<repo>` в ней (без shell, аргументы массивом; `owner`, `repo` и хост
  проверяются как простые имена, git не спрашивает пароль в терминале —
  `GIT_TERMINAL_PROMPT=0`). Шаги и ошибки (с хвостом вывода `gh`)
  показываются в диалоге; клонирование идёт задачей на сервере, диалог можно
  скрыть и открыть снова.
- **«Указать свой клон»** — путь к корню существующего клона: сервер проверяет,
  что это git-репозиторий и что один из его remote-ов — тот же `owner/repo`
  (иначе отказ: «Папка — клон другого репозитория…»). Ничего в клоне не
  меняется. Подходят адреса `https://`, `ssh://`, `git@host:` (с `.git` и без,
  регистр не важен), путь — ровно `owner/repo` на хосте PR-а.
- **Привязка** запоминается в `~/.local-review/pr-clones.json` — на
  репозиторий (все его PR-ы пользуются одним клоном), путь — настоящий (без
  символических ссылок); испорченный файл не затирается молча, а
  сохраняется рядом как `pr-clones.json.corrupt`. Вы остаётесь на странице
  PR-а: дифф и комментарии прежние, LSP-запросы идут по клону (корень — клон,
  пути PR-а — пути клона), файлы вне диффа читаются из клона. «⋯» на плашке:
  «Указать другой клон…», «Клонировать заново…», «Отвязать клон» (папка
  остаётся).
- **Клон не на коммите PR-а** (другая ветка, PR обновился): плашка
  предупреждает, что файлы могут не совпадать, и предлагает кнопку
  `gh pr checkout <номер>` (с `--repo`: в клоне форка с `upstream` берётся PR
  нужного репозитория) — сама ветка не переключается никогда; при
  незакоммиченных изменениях в клоне переключение отказывается. Пока клон не
  на head, серверу отправляется показанный текст файла (как в Staged).
- **Доверие.** Клон чужого PR-а — чужой код, поэтому серверы из его
  `node_modules/.bin` по умолчанию **не запускаются**: только из `PATH`
  (индикатор «LSP не доверен», если сервер есть лишь в клоне), и серверы из
  `PATH` получают настройки, не исполняющие код проекта (см. ниже). Флажок на
  плашке **«Доверять этому репозиторию»** снимает оба ограничения; выбор
  запоминается вместе с привязкой по настоящему пути папки (указали другую
  папку — снова не доверено; тот же клон через символическую ссылку — та же
  папка). «Отвязать клон» забывает и доверие, серверы клона
  останавливаются. Для локальной папки всё как раньше: `node_modules/.bin`,
  затем `PATH`, без ограничений.

Какие серверы используются (ищутся в `<репозиторий>/node_modules/.bin`, затем
в `PATH`; для недоверенного клона PR-а — только в `PATH`):

| Язык | Сервер | Как поставить |
| --- | --- | --- |
| TypeScript / JavaScript, TS 7 | `tsc --lsp --stdio` из `node_modules` репозитория | `npm i -D typescript` (сам TypeScript 7) |
| TypeScript / JavaScript, TS ≤ 6 | `typescript-language-server --stdio` | `npm i -D typescript typescript-language-server` (или `-g`) |
| Java | `jdtls -data ~/.local-review/jdtls/<хеш репозитория>` | Eclipse JDT LS в `PATH`, нужен JDK 21+ |
| Go | `gopls` | `go install golang.org/x/tools/gopls@latest` |
| Python | `pyright-langserver --stdio` | `npm i -g pyright` или `pip install pyright` |
| Rust | `rust-analyzer` | `rustup component add rust-analyzer` |

Процесс один на пару «репозиторий × сервер», стартует при первом наведении или
переходе и останавливается после 10 минут простоя (`shutdown` → `exit`) и при
выходе из `review`. Упавший сервер не перезапускается в цикле: 10 секунд
запросы сразу получают ошибку с его stderr, потом следующий запрос запускает
его заново. Пока сервер индексирует проект (о чём он сообщает через
`$/progress`), запрос ждёт окончания индексации (до 20 с), иначе tsserver
отвечает «определение — это строка import».

Ограничения:

- **F12** (и `Shift+F12`, `Ctrl+F12`) в Chrome и Firefox может сначала
  открыть DevTools — страница не может это запретить. Основной путь — `Ctrl`+клик и меню по правой кнопке;
  сочетание можно переназначить в настройках.
- **Java (jdtls)** не устанавливается и в автотестах вживую не проверяется: ему
  нужен JDK 21+, первый запуск на Maven/Gradle-проекте занимает от 10 секунд до
  минуты (в шапке — «индексация…»), индекс лежит в
  `~/.local-review/jdtls/<хеш репозитория>`, в репозиторий ничего не пишется.
  Переход в классы JDK (`jdt://…`) открыть нельзя — будет сообщение.
- **Навигация по тексту** (PR без клона) — догадка: одноимённые объявления в
  разных файлах не различаются, многострочные объявления находятся по первой
  строке, файлов вне диффа нет; читаются только первые 300 файлов диффа.
- **Недоверенный клон**: typescript-language-server из `PATH` получает
  `tsserver.path` своей установки (иначе он сам загрузил бы
  `node_modules/typescript` клона); если своего TypeScript у него нет
  (поставлен без `typescript` рядом) или сервер из `PATH` лежит внутри самого
  клона, он не запускается вовсе — индикатор «LSP не доверен», в подсказке
  причина; jdtls — без импорта Gradle и Maven (они
  исполняют скрипты сборки и плагины; навигация по библиотекам тогда беднее);
  rust-analyzer — без build-скриптов (`build.rs`), proc-макросов и `cargo
  check`; gopls — с `GOTOOLCHAIN=local` (строка `toolchain` в `go.mod` не
  скачает и не запустит другой Go). Это не песочница: rust-analyzer всё равно
  вызывает `cargo metadata` (а `.cargo/config.toml` клона может назначить
  `rustc-wrapper`, `rust-toolchain.toml` — другой toolchain), gopls — `go
  list` (cgo-директивы, `go.work`), pyright запускает `python` для путей
  поиска и читает `pyrightconfig.json`. Открывайте недоверенный клон только с
  серверами, которым это безопасно, или не включайте LSP для чужого кода.
- Первый запрос в большом репозитории ждёт индексацию: tsserver — от 2 до 15
  секунд.

## Разработка фронта

Нужны два процесса, каждый в своём терминале:

```bash
npm run dev:server         # API на :4321, отдаёт репозиторий, из которого запущен
npm run dev:frontend       # Vite на http://127.0.0.1:5173, /api проксируется на :4321
npm run typecheck          # tsc
npm run test:web           # vitest: чистая логика диффа, дерева файлов, роутинга
```

`dev:frontend` сам API не поднимает: без `dev:server` запросы к `/api` падают.
Прокси всегда идёт на `:4321` — если там уже работает другой `review`
(например, глобально установленный), страница получит его API, а
`dev:server` молча займёт следующий свободный порт. Перед запуском останови
чужой `review`. `dev:server` при старте проверяет, что UI собран
(`tools/local-review/dist/`); после `npm install` он уже собран, иначе —
`npm run build` один раз.

Исходники — `tools/local-review/web/src/`: `screens/` (экраны), `diff/` (дерево
файлов, панель диффа, комментарии), `diff/cm/` (расширения CodeMirror: номера
строк, свёртка, выделение, виджеты комментариев, подсветка вхождений, тема),
`review/` (состояние дифф-экрана), `settings/` (страница настроек: контейнер,
который держит черновик и сохраняет всё одной кнопкой, и по управляемой секции
на настройку),
`api/` (клиент и типы API).

## GitHub PR: страница «Обсуждение»

Третий сегмент переключателя в шапке PR-а — «Обсуждение | Все изменения |
Коммиты». Страница открывается вместо диффа (адрес получает
`&view=conversation`, это шаг истории браузера: «Назад» возвращает к диффу) и
показывает то же, что вкладка Conversation на GitHub:

- описание PR-а, общие комментарии и ревью с вердиктом или текстом — одной
  лентой по времени;
- ревью-треды: файл, строки, последние строки hunk-а и реплики. Решённый тред
  свёрнут в одну строку, «устарел» — его строки уже нет в текущем диффе.
  «Открыть в диффе» открывает файл на строке треда;
- справа — ревьюеры с вердиктами, проверки последнего коммита и метки. Открытая
  панель «Комментарии» встаёт на место этой колонки.

**Только чтение.** Ответить, решить тред или одобрить PR отсюда нельзя — для
этого ссылка на GitHub у каждой реплики.

**Когда ходит в GitHub.** Только когда страницу открыли: открытие PR-а и
возврат на вкладку обсуждение не запрашивают. Страница — один запуск
`gh api graphql` (50 записей ленты и 50 тредов); следующая запрашивается, когда
долистано 90% показанного, и так до конца — потолка нет. Ответ кэшируется на
сервере на 2 минуты, «Перечитать PR» читает заново. Пока один из двух списков
GitHub (лента и треды) прочитан не до конца, записи другого, которые позже
прочитанного, придерживаются, чтобы порядок не менялся при дозагрузке.

**Комментарий агенту.** Кнопка «Агенту» у описания, комментария, ревью и треда
открывает форму обычного локального комментария:

- под тредом — комментарий к файлу и строкам треда: он виден и здесь, и в диффе
  на этой строке. У устаревшего треда строки нет, комментарий привязывается к
  файлу целиком;
- под описанием, общим комментарием или ревью — общий комментарий.

Вместе с комментарием сохраняется снимок замечания (автор, ссылка, текст; у
треда — вся переписка и строки кода), так что экспорт не зависит от того, что
с замечанием стало на GitHub позже. В экспорте замечание идёт цитатой между
якорем и текстом:

```
src/billing/retry.ts:L41-L42
> Замечание @dpetrov — https://github.com/acme/billing/pull/482#discussion_r1
> Нет верхней границы задержки, нужен cap.
>
> @mkozlov: Согласен, ограничу 15 минутами.
Сделай cap константой MAX_DELAY_MS и добавь тест на 10-ю попытку
```

У комментария без строки (устаревший тред) в цитату перед текстом замечания
добавляются строки кода треда — по ним агент находит место. Комментарии,
написанные не на этой странице, экспортируются как раньше.

Не показываются: реакции, события ленты (пуши, смена меток), реплики треда
сверх первых 100 (сколько не показано — написано под тредом, со ссылкой на
GitHub) и проверки сверх первых 100.

## Режим «коммиты»

Четвёртый режим в шапке — просмотр диффа по коммитам, доступный и для
локальной папки, и для GitHub PR. Под шапкой появляется строка с выбранным
коммитом или диапазоном («Коммиты 3–5 из 12», хеши, сообщения), кнопками
«скопировать хеш» и «Вся история». Клик по строке разворачивает рельс истории
(и сворачивает обратно; выбор запоминается в браузере, по умолчанию свёрнут):
кружок на коммит, под ним сообщение в две строки с многоточием, нижней
строкой — хеш, автор и дата.

- Клик по коммиту — дифф этого коммита относительно его первого родителя.
- Протяжка мышью по кружкам — диапазон; работает в обе стороны, 1→3 и 3→1
  дают одно и то же (дифф от первого родителя нижнего коммита до верхнего).
- Клик внутри выбранного диапазона обрезает его от нижней границы: 1–9 плюс
  клик по 4 даёт 1–4.
- Клик по любой границе диапазона оставляет только этот коммит.
- Клик по единственному выбранному коммиту возвращает выбор на последний.
- `←` / `→` — перейти на соседний коммит, `Shift` + `←` / `→` — тянуть диапазон
  (фокус на развёрнутом рельсе).
- Пустого выбора не бывает: минимум один коммит выбран всегда, по умолчанию —
  последний коммит ветки (или PR-а).
- Наведение на коммит — полный текст сообщения; кнопка копирования в строке
  сводки — хеш в буфер обмена (для диапазона копируется `A..B`).
- «Вся история» — боковой дровер со всеми коммитами. Открывается с замком:
  строки только читаются и копируются, случайный клик не схлопывает диапазон.
  Замок снимается кнопкой в шапке дровера.

Для локальной папки рельс показывает коммиты текущей ветки от точки
ветвления — `merge-base(<base>, HEAD)..HEAD`, где `<base>` берётся из шапки
(`--base`). Если точка ветвления не найдена, показываются последние коммиты
`HEAD`; длинная история обрезается по лимиту, об этом написано внизу дровера.
Для GitHub PR рельс — это коммиты самого PR-а (`gh api .../pulls/<n>/commits`);
GitHub не отдаёт больше ~250 коммитов от текущего конца ветки — при обрезке
это тоже видно в дровере.

Выбор диапазона нигде не сохраняется: он живёт только в памяти вкладки
(в адрес страницы не попадает), поэтому перезагрузка страницы или возврат на
этот экран позже сбрасывает выбор на последний коммит, как при первом
открытии.

Особые случаи:

- **Первый (root) коммит** сравнивается с пустым деревом — родителя нет, но
  коммит выбирается как любой другой.
- **Мердж-коммиты** диффятся с первым родителем — точно так же, как обычный
  коммит со своим единственным родителем; отдельного «комбинированного»
  диффа, как на вкладке Files changed у мерджа в GitHub, здесь нет. У чистого
  мерджа, который действительно что-то принёс из вливаемой ветки, этот дифф
  не пуст.
- **Незакоммиченные изменения** (только для локальной папки) дифф по
  коммитам не показывает. Если они есть, под рельсом висит плашка с
  предупреждением. Плашка закрывается, но живёт только в памяти вкладки —
  после перезагрузки вернётся.
- **Комментарии вне выбора** не рисуются в диффе, но считаются в шапке:
  «N вне выбора». Клик по счётчику расширяет выбор до диапазона, где они видны.
  Сами комментарии по-прежнему общие для всех выборов диапазона в этой папке
  / этом PR-е — выбор коммитов их не фильтрует и не разносит по разным файлам.
- **detached HEAD** (локальная папка) режим не поддерживает.

## Формат экспорта

И `.md`-файл, и буфер обмена содержат одно и то же:

```
src/features/auth/model/store.ts:L42
Не мутируй входной dto, верни новый объект

src/shared/api/client.ts:L88-L96
Этот retry дублирует логику из interceptor, вынеси
```

- `path:L<n>` — одна строка, `path:L<start>-L<end>` — диапазон.
- Комментарий к файлу целиком экспортируется как просто `path` (без `:L`).
- Если есть общие комментарии, они идут первыми (от старых к новым) под
  заголовком `## Общие комментарии`, а комментарии к коду — после них под
  `## Комментарии к коду`. Без общих комментариев формат ровно такой, как выше:
  никаких заголовков.

  ```
  ## Общие комментарии

  Проверь обработку ошибок во всём PR

  ## Комментарии к коду

  src/shared/api/client.ts:L88-L96
  Этот retry дублирует логику из interceptor, вынеси
  ```
- Номера строк — реальные номера в файле после изменений, а не позиции внутри
  диффа. Это одинаково верно для локального диффа и для диффа из GitHub: их
  разбирает один и тот же парсер.
- **Промпт при копировании** (шестерёнка в шапке → страница `#/settings`): свой текст,
  который добавляется **в конец** — после комментариев, через пустую строку. И в
  буфер, и в `.md`-файл: они по-прежнему содержат одно и то же. Один на все
  папки и PR-ы, хранится в `~/.local-review/settings.json`. Пустой промпт ничего
  не меняет: экспорт ровно такой же, как без него.
- «Сгенерировать .md» (меню «Ревью») кладёт `review-<YYYY-MM-DD-HHmm>.md` и показывает путь.
  Экспорт (и в файл, и в буфер) **не** меняет комментарии.

## Хранилище

Файлы, не `localStorage` — комментарии переживают перезагрузку страницы и
перезапуск сервера в обоих режимах. Стораджи двух режимов не пересекаются:
единственное место, где выбирается путь, — `lib/stores/factory.js`.

При подтверждении выбора папки тула прописывает, что `.local-review/` не нужно
коммитить. Куда именно — выбирается на странице настроек (`#/settings`,
шестерёнка в шапке) и хранится в `~/.local-review/settings.json`
(`gitignoreTarget`):

- `project` (по умолчанию, историческое поведение) — строка `.local-review/`
  дописывается в **корневой** `.gitignore` репозитория. Даже если выбран
  подкаталог, вложенный `.gitignore` не создаётся; вне git-репозитория не
  пишется ничего.
- `global` — строка дописывается в общий для машины файл: `core.excludesFile`,
  а если он не задан — `$XDG_CONFIG_HOME/git/ignore` (иначе
  `~/.config/git/ignore`), и тогда же этот путь прописывается в глобальный
  git-конфиг (`git config --global core.excludesFile`). Репозитории при этом не
  меняются вообще.

Там же, на странице настроек, — «Режим просмотра по умолчанию»
(`defaultViewMode` в `~/.local-review/settings.json`): `all` (по умолчанию, все
файлы лентой) или `single` (один файл на экране). Это режим, в котором экран
диффа открывается, пока в браузере нет запомненного выбора.

И там же — «Вид файла: „Код“ / „Просмотр“» (`renderModeForAllFiles`): `true` (по
умолчанию) — переключатель в шапке любого файла меняет вид сразу у всех файлов,
у которых есть просмотр, и в ленте, и в режиме одного файла; `false` — у каждого
файла свой переключатель. Сам выбранный вид не сохраняется: он живёт до
перезагрузки страницы или смены диффа.

Страница настроек сохраняется целиком: все настройки правятся в черновике, одна
кнопка «Сохранить» (или `Ctrl+Enter`) отправляет один `PUT /api/settings` только
с изменившимися ключами, «Отменить правки» возвращает сохранённые значения. Уход
со страницы с несохранёнными правками спрашивает подтверждение.

В обоих случаях строка не дублируется (учитываются написания `.local-review`,
`.local-review/`, `/.local-review`, `**/.local-review/` и т. п.), последний
перевод строки и CRLF сохраняются, отсутствующий файл создаётся. Смена режима
ничего не удаляет: строка, уже записанная в другое место, остаётся там. Факт
записи показывается в UI. Простой обзор каталогов не пишет никуда.

## Что тула не делает

С git она работает только на чтение (`git diff`, `git show`, `git rev-parse`,
`git ls-files`, `git merge-base`): не коммитит, не переключает ветки, не пишет в
исходники. Исключение — клон PR-а, и только по кнопке: «Клонировать…» делает
`gh repo clone` в новую папку и `gh pr checkout` в ней, кнопка
`gh pr checkout <номер>` на плашке переключает указанный клон.
Единственная запись в репозиторий — строка `.local-review/` в корневом
`.gitignore`, и только после подтверждённого выбора папки; в режиме `global`
её нет и там — вместо неё правится общий для машины файл игнора (и, если
`core.excludesFile` не задан, глобальный git-конфиг).

**Локальный режим в сеть не ходит вообще.** **Режим PR ходит в сеть
исключительно через подпроцесс `gh`** — прямых HTTP-запросов к `api.github.com`
в коде нет, токен не читается и не хранится. Полные тексты файлов PR-а (для
построчного диффа) берутся через `gh api .../contents` на merge-base и на head. В GitHub на запись не отправляется
ничего: комментарии живут только локально. Существующие комментарии ревьюеров
показываются на странице «Обсуждение» (см. ниже) — только для чтения, и
запрашиваются у GitHub лишь когда её открыли.

Language server — сторонний процесс, который тула запускает в корне
репозитория (локальной папки или клона PR-а, и только если он уже установлен у
вас) и который читает файлы проекта. Из `node_modules/.bin` клона PR-а сервер
запускается только после «Доверять этому репозиторию». Пути, которые браузер передаёт в `/api/lsp` и
`/api/file`, проверяются: только внутри корня репозитория, без `..`,
абсолютных путей и символических ссылок наружу и никогда — внутрь `.git/`
(там адреса remote-ов с токенами); корень должен быть корнем
git-репозитория. Элементы иерархии вызовов уходят в браузер с HMAC-подписью
и принимаются обратно только с ней: подделанный элемент мог бы указать
серверу на любой файл.

Сервер слушает только `127.0.0.1` и отклоняет кросс-сайтовые запросы по
заголовкам `Origin` / `Sec-Fetch-Site`. Против DNS rebinding (чужой домен,
перенаправленный на `127.0.0.1`, для браузера «свой» origin) `/api/*` отвечает
только на `Host`: `localhost`, любой IP-адрес (`127.0.0.1`, `[::1]`, адрес
машины в сети — его не перепривязать через DNS) и имя из `--host`, если оно
задано; остальное — 403. Если сервер слушает `0.0.0.0` и к нему ходят по
имени машины, а не по адресу, это имя надо передать в `--host`.

## Проверка

```bash
node tools/local-review/smoke.js
```

230 проверок. Скрипт создаёт временный git-репозиторий (коммиты, изменения,
переименование, удаление, untracked, бинарник, CRLF, кириллица с пробелами, файл
на 3000 строк), поднимает на нём настоящий сервер и дёргает все эндпоинты.
GitHub-сценарии гоняются на фикстурах — `lib/gh.js` запускает бинарь из
`LOCAL_REVIEW_GH_BIN`, поэтому **реальная сеть в тесте не используется**, а
прод-путь остаётся честным подпроцессом `gh`.

LSP-слой проверяется там же на подставном language server
(`smoke-fixtures/lsp-fixture.js`, кладётся в `node_modules/.bin` временного
репозитория): framing `Content-Length`, поиск сервера (`node_modules/.bin`,
`PATH`, TS 7 → `tsc --lsp`, `-data` для jdtls), ленивый старт, `didOpen` /
`didChange` показанного текста, падение сервера, остановка после простоя,
`no-clone` для PR и отказ на путях вне репозитория и в `.git/`; ссылки,
реализации, иерархия вызовов в обе стороны (превью строк, места вне
репозитория, подпись элементов), ответ «не поддерживается» при выключенных
capabilities. Клон PR-а — тоже там: `gh repo clone` и `gh pr checkout`
фикстуры делают настоящий `git clone` / `git checkout` (поле `exec` в её
манифесте), проверяются задача клонирования, отказ для непустой папки и для
«своего клона» с другим remote, клон не на head и `gh pr checkout` с отказом при
незакоммиченных правках, доверие (без него сервер из `PATH`, с ним — из
`node_modules/.bin` клона), LSP-запросы и `/api/file` по клону, комментарии к
файлам вне диффа и их экспорт (для PR и для папки). Поиск по тексту без клона —
чистая логика фронта, в vitest (`nav/textSearch.test.ts`,
`nav/textSources.test.ts`). Там же — отказ по чужому `Host`. С настоящим сервером
(TypeScript 7 и typescript-language-server + TypeScript 5) это проверено
вручную на демо-репозитории.

Каждый из девяти инвариантов имеет именованную проверку: экспорт не меняет
комментарии (в обоих режимах); массовое удаление только с явным `confirm`;
комментарии переживают рестарт; номера строк в экспорте — реальные номера в
файле; стораджи двух режимов не пересекаются; тула не выполняет пишущих
git-команд и не меняет файлы проекта; runtime-зависимостей ноль (только
`devDependencies` для сборки UI) и ни одного прямого HTTP-запроса к GitHub; обзор каталогов не отдаёт содержимое файлов; отказы `gh`
(не установлен, нет логина, лимит API, нет сети, 404) дают читаемое сообщение.
Ненулевой код выхода при любом расхождении.

## API (если понадобится дёргать руками)

Дескриптор источника едет query-параметрами **во всех** методах, включая POST и
DELETE: `?source=local&root=<путь>&mode=&base=` либо
`?source=pr&host=&owner=&repo=&number=`. Без него берутся значения, с которыми
стартовал сервер.

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/state?<дескриптор>` | список изменённых файлов + счётчики комментариев; у файла `fingerprint` (версия его диффа), `viewed` и `additions` / `deletions` — добавленные и удалённые строки (`null` у бинарного и у untracked-файла) |
| GET | `/api/diff?file=&<дескриптор>` | дифф одного файла с реальными номерами строк + полные тексты `oldText` / `newText` |
| GET | `/api/comments?<дескриптор>` | все комментарии этого источника |
| POST | `/api/comments?<дескриптор>` | создать `{file, startLine, endLine, text}`; общий комментарий — `{general: true, text}` (в хранилище `file: null`) |
| PUT | `/api/comments/<id>?<дескриптор>` | изменить текст |
| DELETE | `/api/comments/<id>?<дескриптор>` | удалить один |
| POST | `/api/comments/clear-all?<дескриптор>` | удалить все, только с `{"confirm": true}` |
| POST | `/api/viewed?<дескриптор>` | `{file, fingerprint, viewed: true}` — отметить просмотренным, `{file, viewed: false}` — снять; отметка своя у каждого вида (working / staged / base с конкретной базой / диапазон коммитов / «все изменения» PR-а) и перестаёт действовать, как только дифф файла меняется |
| GET | `/api/export/text?<дескриптор>` | markdown-текст для буфера (с промптом в конце, если он задан) |
| POST | `/api/export/file?<дескриптор>` | записать `review-<...>.md` |
| POST | `/api/lsp?<дескриптор>` | вопрос language server: `{method: "definition" \| "hover" \| "references" \| "implementation" \| "prepareCallHierarchy", path, line, character, text?}` — позиция LSP (с нуля, UTF-16), `text` — показанная версия файла (staged, коммиты); `{method: "incomingCalls" \| "outgoingCalls", path, item, token, text?}` — `item` и `token` из предыдущего ответа как есть. Ответ `{ok: true, server}` плюс `locations` (места: `path` или `path: null` и `external` — вне репозитория либо, с `gitInternal: true`, внутри `.git/`, у ссылок и реализаций — `preview: {text, start}`), `hover`, `items` (узлы: `name`, `kind`, `detail`, место, `item`, `token`) или `calls` (`[{node, sites}]`); либо `{ok: false, reason: "no-clone" \| "unsupported" \| "not-supported" \| "no-server" \| "failed" \| "timeout", message, hint}` |
| GET | `/api/lsp/status?<дескриптор>` | какие серверы найдены (`found`: где), их состояние (`stopped` / `starting` / `indexing` / `ready` / `failed`) и что запущено; без дескриптора — только `PATH` |
| GET | `/api/file?path=&<дескриптор>` | файл рабочей копии целиком (вне диффа), только внутри репозитория (не `.git/` — 403); для PR — из его клона, без клона 409 |
